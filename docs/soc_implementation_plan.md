# План реализации Adjoint Matching для VE-мостов

Цель — дообучать BM/ABM по дифференцируемой терминальной награде, начиная с копии денойзера учителя. Первый эксперимент — согласованность с JPEG. Готовый результат включает обучение из YAML, проверку на validation split, продолжение с чекпойнта и восстановление изображения сохранённым учеником. Реализовывать в порядке разделов 1–6. Первый исполняемый результат — одна итерация AM с аналитическими моделями, следующий — та же итерация с настоящим Denoiser.

Рабочая ветка — `soc`. В рабочем дереве уже есть `src/bridge_soc/{config,initialization,__init__}.py`, `configs/soc/initialize.yaml` и тесты инициализации. Использовать их, включая поддержку EMA/raw, режимов BM → BM, ABM → ABM, BM → ABM и нулевых каналов наблюдения. Учитель заморожен, ученик обучаем, обе сети в `eval()` для детерминированного dropout. `bridge_soc` импортирует общие компоненты из `bridge_restore`. Перед реализацией сверить актуальные файлы и локальные изменения.

## 1. Начать с одного шага обучения

**Файл** — `src/bridge_soc/adjoint_matching.py`. Центральная функция вычисляет loss. Шаг оптимизатора принадлежит тренеру. Сначала реализовать функцию и её тест с короткой искусственной траекторией. Для теста достаточно фикстуры, реализующей описанный ниже контракт сэмплера.

```python
adjoint_matching_loss(teacher, student, sampler, reward, batch, *,
                      beta, reward_input, generator) -> AMResult
```

Минимальные договорённости:

| Объект | Контракт |
|---|---|
| batch | Словарь. Обязателен xT формы [B,C,H,W] в диапазоне модели. Остальные поля определяет награда. Примеры во всех результатах сопоставляются в порядке исходного батча. |
| teacher, student | Существующий интерфейс denoiser(xt, t, observation=xT), время имеет форму [B]. Учитель доступен для производных по состоянию. |
| reward | Вызов reward(image, batch) выдаёт один скаляр на изображение, форма [B], больше — лучше. Каждый скаляр зависит от своего примера. Параметры внешней модели награды, если есть, заморожены. |
| sampler | Знает сетку и число интервалов N. rollout(student, observation, indices, generator) возвращает данные для AM. sample(student, observation, generator) возвращает SamplingResult для инференса. |
| AMResult | loss — скаляр с графом по параметрам ученика. reward_values — отделённый тензор [B]. |

**Последовательность внутри функции:**

1. Для каждого изображения независимо выбрать индекс `k = torch.randint(N, (B,), device=device, generator=generator)`. Выбор равномерен среди начальных узлов всех интервалов, включая последний положительный узел. Повторения между изображениями допустимы.
2. Получить rollout ученика под `no_grad()`. Конечное состояние x_N сырое. Использовать обычные detached-тензоры, которые можно затем передать в autograd по входу.
3. В функции `_terminal_adjoint` вычислить терминальный вектор по рецепту ниже. beta строго положительна. Поддержать оба значения reward.input независимо от sampling.clip_output.

```python
with torch.enable_grad():
    terminal = rollout.terminal.detach().requires_grad_(True)
    image = terminal.clamp(-1, 1) if reward_input == "clipped" else terminal
    values = reward(image, batch)  # [B]
    a_N, = torch.autograd.grad(-values.sum() / beta, terminal)
```

Сумма сохраняет масштаб отдельного примера. В режиме clipped производная clamp входит в терминальный VJP и обнуляет вклад координат за пределами диапазона. В режиме raw внутри реализации награды также сохранять значения вне диапазона. Отделить a_N и значения наград.

4. Передать a_N в `_propagate_adjoint`. Принятое граничное приближение — **a[N−1] = a[N]**. Оно соответствует правому шагу Эйлера для идеального ABM с ограниченным гессианом условной лог-плотности. Для фактического BM/ABM это инженерный выбор. В нуле сеть не вызывается. Остальные шаги через правые узлы описаны в разделе 3.
5. Одним батчем собрать выбранные x[k], t[k], a[k] в исходном порядке. Вычислить D0 под no_grad, Dθ — с графом. Выполнить вычисления в float32 в первой версии. Скаляры времени расширять по не-батчевым осям через существующий broadcast.
6. Вычислить следующую потерю (сумма квадрата по пикселям и каналам, среднее по примерам):

```text
dt_i = t[i+1] − t[i] < 0
residual_b = Dθ(x[k],t[k],xT) − D0(x[k],t[k],xT) + t[k]² · a[k]
ell_b = sum(residual_b²) / t[k]³
loss = mean_b(N · abs(dt_k) · ell_b)
```

Для проверки знаков: управление по ходу генерации равно (b_rev^0 − b_rev^θ)/sqrt(2t). Подстановка в половину квадрата нормы u + sqrt(2t)·a даёт приведённую формулу. При фиксированных траектории и целях ожидание по индексу от N·abs(dt_k)·ell_k равно полной сумме по интервалам, поскольку вероятность выбора равна 1/N. То же верно для градиента с stopgrad. Эта несмещённость относится к дискретной квадратуре. Отдельного деления на beta в регрессии нет.

**Проверка этапа.** Тестовая награда — линейная или отрицательный квадрат расстояния. Проверить знак a_N, независимость масштаба от B, значения градиента в raw/clipped на внутренних и внешних координатах, только ученик получает параметрический градиент после backward. При нулевой награде с нулевым градиентом и совпадающих сетях loss равен нулю.

## 2. Реализовать прямую траекторию и сохранить старый сэмплер

**Существующий файл** — `src/bridge_restore/sampling.py`. Вынести в общие функции построение положительной сетки и один стохастический шаг Эйлера–Маруямы. Сохранить интерфейс SDESampler, порядок арифметики и генерации шума, режим модели до и после sample, NFE и поведение clipping. Использовать VEBridge.reverse_drift, VEBridge.diffusion и прежний broadcast.

**Новый файл** — `src/bridge_soc/sampling.py`, отдельный класс SOCSampler без наследования. У sample и rollout общий цикл генерации. Различаются объём сохранённых состояний и постобработка результата. При одинаковом seed шум назначается одним и тем же исходным примерам независимо от выбранных k.

```text
positive_grid = linspace(T − start_offset, sigma_min, num_steps + 1)
soc_grid      = concat(positive_grid, [0])
N             = num_steps + 1
x_start       = observation
для i = 0 .. N−2:
    dt = t[i+1] − t[i]
    x[i+1] = x[i] + dt · reverse_drift(student, x[i], t[i], xT)
                  + sqrt(2t[i]) · sqrt(−dt) · independent_noise
последний шаг, δ = t[N−1] = sigma_min:
    x[N] = x[N−1] − δ · reverse_drift(student, x[N−1], δ, xT)
         = 2Dθ(x[N−1],δ,xT) − x[N−1]
```

Оба сэмплера выполняют num_steps шумовых шагов и один финальный вызов модели. В старой задаче финальный вызов возвращает D(x,δ,xT); в SOC он даёт детерминированный шаг Эйлера. SOC sample возвращает изображение с выбранным clip_output и NFE. SOC rollout возвращает сырое x[N] даже при clip_output=true. Baseline учителя для SOC сравнивать с учеником на одном SOC-сэмплере.

**Проверка этапа.** Независимой короткой ручной рекурсией с фиксированным генератором проверить старую последовательность шума и финальный денойзер. Для SOC проверить последний знак, отсутствие нового шума и обращения к сети в нуле, NFE, равенство сырого результата sample и rollout при одинаковых шуме и входах. При clip_output=true сравнить с clamp от сырого результата.

## 3. Батчевый обратный проход с сокращением активной части

**SOCRollout** в `bridge_soc/sampling.py` должен предоставлять сетку, сырой конец, выбранные состояния и сохранённые правые узлы с индексами исходных примеров. В `adjoint_matching.py` использовать эти данные для VJP учителя. Порядок реализации:

1. Отсортировать индексы k по возрастанию один раз. На узле j достаточно сохранить строки с k ≤ j. Полный rollout вести в исходном порядке для воспроизводимого назначения шума; для хранения выбирать строки в отсортированном порядке. Если сохраняется срез большого тензора, скопировать нужные строки, чтобы освободить память остальных. Конец для оценки награды и метаданные батча остаются согласованы по исходному порядку.
2. Пример с k=N−1 получает цель сразу после копирования a[N] в a[N−1]. Цикл VJP идёт от i=N−2 до min(k) включительно. При min(k)=N−1 цикл пуст. Активны примеры с **k ≤ i**, а читаем сохранённое состояние **x[i+1]** этих примеров.
3. Для активных строк вычислить VJP по входу учителя. Наблюдение остаётся фиксированным:

```python
with torch.enable_grad():
    right = right_states.detach().requires_grad_(True)
    drift = bridge.reverse_drift(teacher, right, right_times, active_xT)
    vjp, = torch.autograd.grad(drift, right, grad_outputs=a_right)
a_left = (a_right + dt_i * vjp).detach()  # dt_i отрицателен
```

4. Сохранить a_left для k=i, продолжить только для k<i. Собрать цели и предсказания ученика в исходном порядке. Индекс регрессии всегда один на пример. Параметры оптимизатора обновляются после всего батча.

**Приёмка основной итерации.** Сравнить векторизованный путь с поэлементным для индексов с повторами, разными краями, B=1 и всех k=N−1. Для проверки именно правого узла взять учителя с якобианом, зависящим от времени или состояния. На фиксированной короткой траектории перебрать все k и сверить среднее loss **и градиента параметров** с полной суммой; сделать последний интервал отличным по длине. Для управления тестом допустимо передать заданные индексы внутреннему вычислению loss. Далее выполнить один шаг оптимизатора на маленьком настоящем Denoiser с тестовой наградой, проверить конечность, обновление ученика и сохранность учителя. Для этих тестов подходят `tests/bridge_soc/test_sampling.py` и `test_adjoint_matching.py`.

## 4. Подключить награду согласованности JPEG и её данные

**Файлы** — `bridge_soc/rewards/jpeg.py`, `bridge_soc/data.py` под `src/`, минимальное изменение `bridge_restore/data/corruptions.py`. JPEGConsistencyReward реализует тот же callable, что и тестовая награда. AM знает только reward(image,batch). Выбор raw/clipped принадлежит конфигу конкретной награды.

1. В JPEGCorruption выделить получение закодированных байтов и декодирование этих же байтов. Старый __call__ сохраняет контракт RGB float32 [0,1], округление round(255*x), настройки Pillow, quality/subsampling и прочие параметры кодека.
2. Для примера SOC после исходного preprocessing выполнить одно JPEG-кодирование. Из одних и тех же байтов получить RGB-наблюдение и целочисленные квантованные DCT-коэффициенты m, таблицы Q и sampling factors по компонентам. Сопоставить таблицу каждой компоненте по её ID; учитывать порядок zigzag или натуральный порядок, который выдаёт выбранная библиотека. Не восстанавливать индексы повторным кодированием декодированного xT.
3. Выбрать и проверить библиотеку чтения коэффициентов на поддерживаемой Python-платформе проекта. Вариант для проверки — libjpeg-совместимый Python reader. Проверить чтение без потери коэффициентов и затем объявить фактическую JPEG-зависимость в pyproject. Конкретная библиотека пока не согласована. Если API принимает только путь, обеспечить изолированные временные файлы при параллельной загрузке.
4. Переиспользовать preprocessor, clean dataset, split manifest, EpochSampler и build_loaders. Поля примера — xT в диапазоне модели, sample_id, нужные тензоры JPEG и x0 для существующих метрик. Для награды, которой достаточно обычного батча, использовать исходный build_data. У первой JPEG-конфигурации фиксированные размеры изображения и sampling factors позволяют складывать Y, Cb и Cr отдельными батчевыми тензорами. Сохранять соответствие наблюдений и метаданных при переносе на устройство.
5. В PyTorch реализовать дифференцируемое отображение кандидата в единицы коэффициентов потока: перевод RGB из масштаба модели в шкалу 0…255, преобразование YCbCr, субдискретизация с правильной фазой, обработка границ/размеров блоков, вычитание уровня 128, блочный DCT 8×8 в согласованной нормировке. Форма сетки блоков и порядок частот должны совпадать с m и Q для каждой компоненты. Не округлять предсказанные коэффициенты: дифференцировать нужно расстояние непрерывного кандидата до интервалов.
6. Вычислить нижнюю и верхнюю границу Q·(m−0.5) и Q·(m+0.5). Сложить квадраты расстояний до интервалов по блокам, частотам и компонентам. Вернуть **минус сумму** на изображение, форма [B]. Существующая ObservationErrorMetric с detach и повторным JPEG остаётся независимой оценочной метрикой.
7. В тестах отделить точную формулу штрафа от приближения реального кодека. Проверить нулевой штраф внутри, знак градиента с обеих сторон, шкалу DC на константном блоке и ориентацию частот на несимметричном паттерне. Для реальных потоков проверить таблицы и формы, совпадение xT со старым путём, основной режим quality=10/subsampling=2 и корректную обработку заявленных форматов. На породивших JPEG изображениях измерить фактический остаток от цветового округления и целочисленного DCT. Точное совпадение непрерывной модели с Pillow не предполагается. Зафиксировать обнаруженную погрешность; допуск, если понадобится, согласуется как изменение награды.

## 5. Конфигурация, обучение и сохранение

1. Расширить `bridge_soc/config.py` конфигом всего эксперимента. Существующий плоский ControlConfig и его загрузчик для `initialize.yaml` должны по-прежнему работать. В полном YAML использовать секции ниже. Значения beta, lr, batch_size и длительность здесь **пример для проверки пайплайна**, подбирать на валидации.

```yaml
seed: 42
output_dir: runs/soc/jpeg
control:
  teacher_checkpoint: runs/my_teacher/checkpoints/last.pt
  teacher_weights: ema
  mode: abm
sampling:
  clip_output: true
reward:
  name: jpeg_consistency
  input: clipped
training:
  device: cuda
  beta: 1.0
  lr: 0.00001
  batch_size: 4
  max_steps: 1000
  validation_interval: 100
  checkpoint_interval: 100
```

   Предусмотреть overrides sampling.num_steps и sampling.start_offset. При отсутствии брать настройки сэмплера из учительского эксперимента. Шкалы VEBridge, включая sigma_min, берутся из чекпойнта учителя. Проверять допустимость режимов, finite beta и lr > 0, положительные размеры и интервалы. Сохранять фактически разрешённую конфигурацию. Пример тренировки разместить в `configs/soc/train.yaml`.

2. В `initialization.py` выделить сборку учителя из уже прочитанного состояния. Сохранить публичные load_teacher и initialize_control_denoiser. Входной CLI использует однократную загрузку чекпойнта для сети, bridge, preprocessing, corruption, split и настроек sampling. Проверять совместимость данных с учителем (включая checksum разбиения и параметры деградации).
3. Добавить `bridge_soc/training.py` с SOCTrainer. train_step получает батч, перемещает данные награды на устройство, обнуляет градиенты, вызывает loss, backward и optimizer.step. Для первой версии достаточно Adam и float32. Логировать шаг, регрессионный loss и среднюю награду. Валидация считает выбранную награду для ученика и учителя на фиксированном подмножестве и одинаковом шуме через SOCSampler. Для raw запрашивать сырой выход даже если пользовательский clip_output=true. Для clipped применять clamp на пути к награде. Изолировать RNG валидации от обучения.
4. Переиспользовать атомарную запись и RNG-утилиты из `bridge_restore/checkpoint.py`. Для SOC ввести явно различимую схему чекпойнта. Сохранить веса/архитектуру/режим ученика, bridge, sampling, ссылку и идентификатор исходного учителя с вариантом EMA/raw, оптимизатор, номер завершённого обновления, конфиг награды, split/corruption, позицию в загрузчике и RNG (в т.ч. состояние отдельного генератора индексов/шума). При resume восстановить ту же перестановку эпохи и следующий батч, проверить совместимость учителя и основных настроек. Для инференса строить ученика из SOC-чекпойнта с его архитектурой и sampling без загрузки учителя.
5. Добавить `bridge_soc/train.py`, точку входа `bridge-soc-train` в pyproject и загрузчик дообученного ученика для вызова SOCSampler.sample. Переиспользовать существующие механизмы split, конфигов, логирования и проверки каталога запуска, где подходят. При запуске с --resume принимать SOC-чекпойнт. Существующие CLI bridge-train и bridge-sample обслуживают прежний формат. В краткой инструкции указать установку JPEG-зависимости, пример запуска, resume и пример инференса из сохранённых весов.

Для запуска обучения — `bridge-soc-train --config configs/soc/train.yaml` с реальным путём учителя. Для автоматического smoke-теста создавать маленький учительский чекпойнт во временном каталоге.
